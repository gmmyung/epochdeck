# EpochDeck 0.1.0-alpha.1

This is EpochDeck's first pre-alpha GitHub release. It is intended for Tailnet-only
evaluation on disposable storage, not public multi-tenant hosting.

## Highlights

- Durable, nonblocking Python logging with W&B-oriented APIs.
- Lossless Arrow/Parquet metric storage with bounded sampled dashboard queries.
- Native image, audio, video, table, histogram, trace, and artifact support.
- Multi-run Canvas charts with configurable alignment, smoothing, axes, and style.
- Split SSD metric/catalog roots and HDD/ZFS content-addressed blob storage.
- Physical backup/restore and portable project import/export workflows.

## Attached assets

The release contains static server archives for
`x86_64-unknown-linux-musl` and `aarch64-unknown-linux-musl`, plus one Python
wheel, one Python source distribution, and `SHA256SUMS`. These files are GitHub
Release attachments only; this release does not publish to PyPI, crates.io, or
npm. Every distribution includes the Apache-2.0 project license. Each server
archive also includes the deterministic third-party dependency notice used for
its statically linked server and embedded dashboard.

Install the attached Python wheel directly from its downloaded path. Verify the
downloaded assets first with
`sha256sum --ignore-missing --check --strict SHA256SUMS`; the command fails if
no named asset is present and safely ignores assets for other architectures.

## Security boundary

EpochDeck has no application-level authentication or multi-user authorization in
this release. Bind the server to loopback, expose it only with Tailscale Serve,
and enforce access with Tailnet grants or ACLs. Do not use Tailscale Funnel or a
public listener.

## Pre-alpha storage and compatibility

Storage is disposable and has no migration promise. Start this release with
empty roots. Before replacing it, stop the service and archive the catalog,
metric, and blob roots together with the exact binary that created them.

The Python API targets practical W&B compatibility but is not a drop-in
implementation of every W&B feature. The importer accepts terminal runs and
requires authoritative histories of at most 100,000 rows per run. It imports
scalar metrics, metadata, native history media, run files, and logged artifacts;
registry-wide features and input-artifact lineage remain outside the current
surface.

Rollback means stopping the new server and restoring the previous binary with
its untouched matching roots. Do not open newer roots with an older binary.
